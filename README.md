# MFC Planner 8.1 — Cloud Database + Wall Gaps

Версия 8.1 собрана поверх Cloud Workspace Base.

## Что реально работает

### Облачные проекты
Frontend умеет:
- указать URL Cloud API;
- проверить доступность сервера;
- зарегистрировать пользователя;
- войти в аккаунт;
- получать только свои проекты;
- создавать облачные проекты;
- открывать их;
- обновлять;
- удалять;
- автосохранять активный проект на сервер;
- перенести существующие локальные планы в облачный аккаунт.

В интерфейсе есть явный статус:
- `● локально`;
- `● облако`.

Когда пользователь вошёл, подпись под проектом указывает сервер и время последней синхронизации.

`localStorage` остаётся только как резервный черновик и для старых локальных проектов.
Именованные проекты при активной Cloud-сессии сохраняются через API в базу данных.

### Backend
`backend/main.py` содержит:
- FastAPI;
- регистрацию и вход;
- безопасное PBKDF2-хеширование паролей;
- случайные 30-дневные bearer-сессии;
- разграничение проектов по владельцу;
- CRUD проектов;
- SQLAlchemy;
- PostgreSQL через `DATABASE_URL`;
- SQLite fallback только для локальной разработки.

### PostgreSQL
Для реального облачного режима backend нужно развернуть на сервере и передать ему PostgreSQL `DATABASE_URL`.
В комплекте есть:
- `backend/.env.example`;
- `backend/Dockerfile`;
- `docker-compose.yml`.

## Боковые интервалы от стен

В блоке «Стеллажи» появилась кнопка:

`Боковые интервалы от стен: ВКЛ / ВЫКЛ`

При ВКЛ используется значение «Отступ слева / справа, м».
При ВЫКЛ боковой отступ становится 0 м.

Изменение сразу влияет на:
- доступную геометрию хранения;
- количество улиц;
- количество секций;
- ШК;
- Optimizer.

Это планировочная настройка. Отключение отступа не означает автоматического соответствия строительным, пожарным или эксплуатационным требованиям.

## Площадь хранения

В верхних KPI вместо площади второго уровня показана «Площадь хранения».
Это фактическая площадь footprint стеллажей, то есть площадь, где физически располагается товар, без проходов между стеллажными улицами.

## Быстрый локальный тест Cloud API

```bash
docker compose up --build
```

API:
`http://localhost:8000`

Health:
`http://localhost:8000/health`

После этого открой frontend и укажи `http://localhost:8000` в поле Cloud API.

## Для доступа с другого компьютера

`localhost` недостаточно. Backend и PostgreSQL должны быть размещены в интернете по HTTPS.
После развертывания укажи публичный HTTPS URL API в MFC Planner.

GitHub Pages может продолжать хостить frontend, но сам по себе GitHub Pages не запускает FastAPI/PostgreSQL.


# MFC Planner 8.2 — Storage Accessibility Engine

Версия собрана поверх 8.1 и сохраняет Cloud Workspace, PostgreSQL backend,
масштабирование штата и настройку боковых отступов.

## Главное изменение

Стеллаж больше не считается допустимым только потому, что прямоугольник
физически помещается на свободную площадь.

Для каждого непрерывного участка стеллажной улицы строится рабочий проход.

Секция остаётся в плане только если:
1. помещаются обе стороны стеллажной улицы;
2. между ними есть проход заданной ширины;
3. в этот проход можно войти хотя бы с одного конца;
4. вход не перекрыт стеной, колонной, офисом, WC или другим жёстким препятствием.

Если входа нет ни с одного конца:
- участок не рисуется;
- секции не входят в вместимость;
- ШК по ним не считаются;
- в аналитике показывается количество исключённых секций.

Центральный проход, коридор персонала, приемка, отгрузка и входные зоны
могут выступать как рабочие точки доступа к стеллажным улицам.

## Визуализация

Рабочие проходы теперь показываются светло-жёлтыми полосами.

Два стеллажных ряда могут стоять вплотную back-to-back.
Это не означает отсутствие доступа:
каждый из них обслуживается со своего внешнего рабочего прохода.

## Боковые интервалы

Отключение бокового отступа от стены не отключает правило доступности.
Если из-за нулевого отступа рабочий проход окажется заперт стенами,
такие секции Storage Accessibility Engine автоматически не поставит.


# MFC Planner 8.3 — Floors + Reports

- В интерфейсе нет отдельной сущности «мезонин»: используются обычные «Этаж 1» и «Этаж 2».
- Этаж 2 добавляется отдельной кнопкой и может быть процессным, складским или смешанным.
- При складском режиме его доступные секции и ШК суммируются с этажом 1.
- Storage Accessibility Engine 8.2 применяется и к хранению этажа 2.
- PDF отчёт: KPI, планы этажей, хранение, поток, персонал, проверки. Сохранение выполняется через системное окно «Сохранить как PDF».
- Excel: многостраничный Excel-совместимый .xls — Сводка, Этажи, Хранение, Процессы, Персонал, Экономика.
- PNG: текущий открытый план этажа.
- Cloud Workspace 8.1 и боковые интервалы сохранены.


# MFC Planner 8.4 — Multi-floor Optimizer

Добавлено сравнение трёх сценариев использования второго этажа:
- только процессы;
- только хранение;
- хранение + процессы.

Цели:
- максимум хранения;
- баланс;
- минимум персонала.

Для каждого сценария рассчитываются секции, вместимость ШК, поток, рекомендуемый штат, ФОТ/OPEX и приближённый вертикальный штраф маршрутов. Лучший сценарий получает score и может быть применён одной кнопкой.

Optimizer не переносит пользовательские зоны между этажами автоматически. Он меняет назначение этажа 2 и показывает последствия.

PDF-отчёт дополнен рекомендованной этажной стратегией. Cloud, Accessibility Engine, боковые отступы и экспорт PDF / Excel / PNG сохранены.


# MFC Planner 8.4.1 — Floor On Demand

Исправление поведения этажей:

- Новый проект всегда стартует только с Этажом 1.
- Этаж 2 не создаётся из-за старых объектов, зон или legacy-поля `mezzanine`.
- Этаж 2 появляется только после явного нажатия «+ Добавить этаж».
- До этого момента:
  - вкладка/кнопка Этаж 2 скрыта;
  - площадь этажа 2 = 0;
  - хранение этажа 2 = 0;
  - секции этажа 2 = 0;
  - ШК этажа 2 = 0;
  - Multi-floor Optimizer просит сначала добавить второй этаж.
- Скрытые старые объекты второго уровня сами по себе этаж не активируют.

Cloud Workspace, Accessibility Engine, отчёты PDF/Excel/PNG и Multi-floor Optimizer сохранены.


# MFC Planner 8.5 — Cloud Projects & Sharing

Реализовано:

- облачные проекты для владельца и приглашённых пользователей;
- роли `owner / editor / viewer`;
- добавление участника по email;
- публичные share-ссылки на просмотр или редактирование;
- история версий;
- восстановление старой версии;
- optimistic locking по `updated_at`;
- защита от ситуации, когда два пользователя одновременно сохраняют устаревшую копию;
- статус `синхронизация / сохранено / ошибка / конфликт`;
- открытие share-ссылки на другом компьютере вместе с адресом Cloud API;
- viewer не может перезаписать исходный проект;
- editor может сохранять;
- удалить проект и управлять участниками может только owner.

Backend обновлён до API 8.5 и использует дополнительные таблицы:
`project_members`, `project_versions`, `share_links`.

Старые таблицы `users`, `login_sessions`, `projects` сохраняются совместимыми, поэтому новые возможности добавляются без обязательного изменения колонок существующей таблицы projects.

Сохранены функции 8.4.1:
Cloud base, Accessibility Engine, этажи по запросу, Multi-floor Optimizer, PDF, Excel, PNG и боковые интервалы.
